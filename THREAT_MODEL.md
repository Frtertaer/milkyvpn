# KAL/2 — модель угроз

## Противник

Государственный цензор на границе сети (ТСПУ-уровень): пассивный DPI,
активные пробы, блокировка по SNI/IP/отпечатку, замедление по эвристике,
периодические «тренировочные» отключения отдельных протоколов.

НЕ покрывается: компрометация сервера или клиента, атаки на конечного
пользователя, корреляция по таймингам на уровне weeks-long наблюдения.

## Что защищаем

1. **Канал не выглядит как VPN.** veil даёт ClientHello в форме Chrome
   (включая PQ-keyshare X25519MLKEM768, GREASE, ALPS, ECH-grease); SNI —
   настоящий домен с настоящим LE-сертификатом и настоящим сайтом-прикрытием.
2. **Активная проба не находит сервис.** Весь не-KAL трафик получает ответ
   decoy-сайта; байт-в-байт неотличимость достигается возвратом уже
   прочитанного префикса в поток (prefix-rewound conn).
3. **Отпечаток ответа не выдаёт.** Сервер отвечает через тот же TLS-стек,
   что decoy; KAL-полёт начинается только после корректного magic+PSK.
4. **Данные не читаются.** Внутренний AEAD поверх TLS-носителя; channel
   binding (TLS exporter в salt) исключает перенос сессии на другой
   TLS-сеанс — relay/MITM не может «припарковать» внутренние ключи к себе.
5. **Повторы не проходят.** Серверный кэш первых полётов (10 мин) +
   монотонные seq записей + тарпит сканеров + лимит 16 соед./IP.
6. **Блокировка IP не фатальна.** Список эндпоинтов + drift может идти
   через CDN-фронт (h2), то есть входной адрес заменяется без смены схемы.

## Известные ограничения

- **Эгресс-репутация**: исходящий IP VPS может быть помечен у отдельных
  CDN (наблюдалось: chatgpt.com managed-challenge на v6-диапазоне
  хостера). Лечится `-egress-family prefer4|only4` и/или `-upstream`.
- **Тайминги/объёмы**: длительные двунаправленные потоки с ~браузерными
  размерами отличаются от «сайта» статистически. Паддинг бакетами
  смягчает, но не устраняет.
- **UDP через veil** идёт только внутри KAL-потоков (нет наружного QUIC) —
  браузер сам откатывается на TCP.
- **Старый wire несовместим**: `a6542c2` (label `kal2-in-v2`, старый
  transcript) ↔ HEAD (`mxs-in-v2` + keyed drift path) — строго paired
  deploy.

## Механизмы → угрозы

| угроза | механизм |
|--------|----------|
| DPI-фингерпринт | uTLS Chrome-пресет, реальный LE сертификат, decoy-сайт |
| активные пробы | steal-слайс по SNI, магия+preauth до любого KAL-байта, tarpit |
| replay | per-flight replay cache, strict-order seq |
| MITM/relay | TLS exporter в key schedule |
| DoS | first-flight deadline, ≤512B pad read, per-IP лимит |
| блок-IP | мульт-эндпоинты, CDN-фронт (drift), клиентский watchdog |
| компрометация пользователя | per-user PSK, ротация = смена `-user` флага |
